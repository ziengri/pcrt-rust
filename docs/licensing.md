# Лицензирование PCRT: демо-версия

## Цель

Первая версия лицензирования защищает программу PCRT от простого копирования на
другой бортовой компьютер. Она не требует постоянного подключения к интернету
и не затрагивает модель ИИ.

Цель защиты - сделать несанкционированное использование заметным и неудобным,
сохранив простой офлайн-процесс выдачи лицензии. Целенаправленную атаку на
устройство с административным доступом нельзя полностью предотвратить без TPM,
аппаратного ключа или обязательной связи с сервером.

## Решение

Лицензия является обычным читаемым файлом с данными об автобусе, сроке и
привязке к оборудованию. Она не шифруется, но подписывается алгоритмом
Ed25519.

Для операций Ed25519 используется crate
[`ed25519-dalek`](https://crates.io/crates/ed25519-dalek). Он отвечает только
за создание и проверку подписи. Формат лицензии, hardware binding и решение о
том, разрешать ли работу, остаются ответственностью PCRT.

Ed25519 использует два связанных ключа:

- приватный ключ - личная печать издателя лицензий; им можно только подписать
  новую лицензию;
- публичный ключ - образец печати; он вшит в программу и позволяет проверить,
  что файл лицензии выдан владельцем приватного ключа.

Приватный ключ не входит в репозиторий, не устанавливается на автобус и не
передаётся пользователю. После однократной генерации ключей публичный ключ
добавляется в исходный код `pcrt-license` как константа.

Пара ключей и подпись имеют фиксированные размеры:

- приватный ключ - 32 секретных байта;
- публичный ключ - 32 байта, допустим для распространения;
- подпись - 64 байта.

В текстовых файлах эти бинарные значения хранятся в Base64. Ключи создаются
средствами `ed25519-dalek` с криптографическим генератором случайных чисел
операционной системы. Не следует генерировать ключи на сайте или вручную.

Для демо лицензия действует до `2027-12-31T23:59:59Z`. Онлайн-продление,
сервер лицензий и отдельный ключ устройства в эту версию не входят.

## Компоненты

```text
crates/
  pcrt-license/          # проверка лицензии в сервисах PCRT
  pcrt-license-signing/  # подпись лицензии; используется только admin-бинарником

bins/
  pcrt-license-admin/    # инструмент владельца ключа для выпуска лицензий
  pcrt-license-tool/     # инструмент на бортовом ПК
```

### `pcrt-license`

Общий crate без приватного ключа. Он:

- описывает формат запроса, лицензии и статуса;
- проверяет Ed25519-подпись по вшитому публичному ключу;
- проверяет срок действия;
- собирает hardware ID текущего компьютера и проверяет привязку;
- возвращает явный статус: допустима ли работа и почему она запрещена.

Этот crate используют `pcrt-door-gateway`, `pcrt-recorder` и
`pcrt-processor`. В первой версии gateway и processor выполняют проверку перед
лицензируемой работой; recorder проверяет статус только для диагностики и
продолжает запись видео.

### `pcrt-license-signing`

Внутренний crate с кодом создания подписи Ed25519. Он не должен быть
зависимостью runtime-сервисов и не должен использоваться на бортовом ПК.
Выделение crate не является защитой само по себе, но исключает случайное
добавление API подписи в общую библиотеку проверки.

### `pcrt-license-admin`

Инструмент только для владельца программы. Он устанавливается исключительно на
закрытый компьютер владельца приватного ключа.

Первая версия содержит команды:

- `generate-keys` - однократно создаёт пару ключей Ed25519;
- `issue` - читает запрос с бортового ПК, создаёт лицензию до конца 2027 года
  и подписывает её приватным ключом;
- `inspect` - показывает содержимое лицензии и проверяет её подпись.

Закрытый ключ передаётся этой программе из защищённого локального файла. Его
содержимое не должно выводиться в логи, передаваться через аргументы командной
строки или попадать в Git.

### `pcrt-license-tool`

Инструмент для техника на бортовом ПК. Он не имеет кода выпуска лицензий и не
содержит приватного ключа.

Первая версия содержит команды:

- `request` - собирает SMBIOS UUID и serial или WWID системного диска, вычисляет их
  хеши и создаёт файл `license-request.json`; по умолчанию читает `BUS_ID` из
  `/etc/pcrt/device.env`, а путь к этому файлу можно передать параметром;
- `import` - проверяет подпись и соответствие оборудования, затем атомарно
  устанавливает лицензию;
- `status` - показывает идентификатор лицензии, автобус, срок и результат
  локальной проверки.

## Подписываемый payload

Payload - это данные лицензии, которые `pcrt-license-admin` сериализует и
подписывает. Внешний контейнер `license.lic` хранит точные байты payload в
`payload_base64` и соответствующую подпись.

Для первой версии payload содержит только необходимое для привязки лицензии к
продукту, перевозчику, автобусу, сроку и оборудованию:

```json
{
  "format_version": 1,
  "product": "pcrt",
  "license_id": "0f6e5ed8-09a7-47a2-9cb6-6b598ed923da",
  "customer_id": "carrier-17",
  "bus_id": "BUS-042",
  "issued_at": "2026-08-12T00:00:00Z",
  "valid_until": "2027-12-31T23:59:59Z",
  "hardware_identifiers": [
    { "type": "smbios_uuid", "sha256": "..." },
    { "type": "system_disk_wwid", "sha256": "..." }
  ]
}
```

`license_id` должен быть уникальным UUID. `customer_id` - стабильный внутренний
идентификатор перевозчика, а не его отображаемое название. `bus_id` должен
совпадать со значением `BUS_ID` из `/etc/pcrt/device.env`.

Файл запроса содержит только данные, полученные на бортовом ПК:

```json
{
  "format_version": 1,
  "product": "pcrt",
  "request_id": "5cb04770-7d60-4f7f-8f96-b583e9bc70ca",
  "bus_id": "BUS-042",
  "hardware_identifiers": [
    { "type": "smbios_uuid", "sha256": "..." },
    { "type": "system_disk_wwid", "sha256": "..." }
  ]
}
```

`request_id` является новым UUID для каждого сформированного запроса. При
замене SSD или всего бортового ПК формируется новый request, а
`pcrt-license-admin` выпускает новую лицензию с новым `license_id`.

В первой версии нет `issuer_key_id`: в программе используется один вшитый
публичный ключ. Нет и `features`: лицензия либо разрешает работу PCRT, либо
нет. Оба поля могут появиться позднее только в новом `format_version` при
реальной потребности в ротации ключа или отдельных платных возможностях.

## Привязка к оборудованию

Лицензия содержит отдельные хеши двух обязательных идентификаторов:

- System/SMBIOS UUID;
- serial системного диска, если доступен, иначе его WWID.

`smbios_uuid` читается из `/sys/class/dmi/id/product_uuid`. После удаления
внешних ASCII-пробелов значение должно иметь UUID-формат `8-4-4-4-12` с
шестнадцатеричными символами. Буквы переводятся в верхний регистр.

`system_disk_serial` или `system_disk_wwid` относится только к накопителю с корневой файловой
системой `/`. Для текущего бортового ПК путь выглядит так:

```text
/ -> /dev/sda1 -> /sys/block/sda/device/serial, затем /sys/block/sda/device/wwid
```

Реализация определяет block device, на котором смонтирован `/`, через его
major:minor в `/proc/self/mountinfo`, разрешает sysfs-ссылку
`/sys/dev/block/<major>:<minor>` и для раздела переходит к родительскому
диску. Затем она ищет serial физического диска в его sysfs-цепочке: в
`device/serial` для SATA/SCSI, у родительского NVMe-контроллера для NVMe и у
родительского MMC-устройства для eMMC. Если serial отсутствует, используется
WWID или eMMC CID того же диска. Этот способ поддерживает прямой root-раздел
на SATA, NVMe или eMMC-накопителе.

Первая версия намеренно не поддерживает root на LVM, RAID, dm-crypt, loop,
overlay или сетевом устройстве. При такой конфигурации, а также при отсутствии
валидного serial и WWID, `pcrt-license-tool request` завершается ошибкой и не
создаёт неполный запрос. Дополнительные диски допустимы: в привязку входит
только диск с корневой файловой системой `/`.

Serial или WWID системного диска очищается только от внешних ASCII-пробелов и
переводится в верхний регистр. Внутренние пробелы сохраняются, потому что они
могут быть частью серийного номера. Для всех идентификаторов отклоняются
пустые значения, значение из нулей и известные заводские заглушки: `UNKNOWN`,
`NONE`, `NOT SPECIFIED`, `DEFAULT`, `N/A`, `TO BE FILLED BY O.E.M.` и `TO BE
FILLED BY OEM`.

После нормализации для каждого значения рассчитывается отдельный хеш:

```text
SHA-256(bytes("PCRT-HWID-v1") + 0x00 + identifier_type + 0x00 + normalized_value)
```

Программа принимает лицензию, только если совпали оба идентификатора того же
типа. Замена системного SSD или бортового ПК требует выпуска новой лицензии.
MAC-адрес не входит в первую версию: его легко заменить или подменить.

`board_serial` и другие DMI serial на проверенном ПК содержат заводское
значение `To be filled by O.E.M.` и не используются.

## Формат файлов

Для демо запрос и лицензия используют JSON. Лицензия является одним контейнером
`license.lic` с исходными байтами payload и подписью:

```json
{
  "format_version": 1,
  "payload_base64": "eyJsaWNlbnNlX2lkIjoiLi4uIn0=",
  "signature_base64": "..."
}
```

`payload_base64` содержит точные байты JSON с данными лицензии, а
`signature_base64` - подпись этих же байтов. Валидация всегда выполняется в
следующем порядке:

1. Декодировать Base64 payload и подписи.
2. Проверить подпись по вшитому публичному ключу через `ed25519-dalek`.
3. Только при успешной проверке разобрать JSON payload.
4. Проверить версию формата, срок и hardware binding.

Подпись создаётся над исходными байтами, а не над повторно сериализованным
JSON. Поэтому изменение порядка полей или форматирования не создаёт ошибок
проверки, а изменение любого значения в payload делает подпись невалидной.

Криптографические зависимости первой версии:

```toml
ed25519-dalek = { version = "2", features = ["rand_core"] }
sha2 = "0.10"
base64 = "0.22"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

`sha2` используется только для хешей hardware ID. `base64` делает бинарные
ключи и подписи пригодными для текстовых файлов. Криптографические алгоритмы
не реализуются собственным кодом.

Файл запроса не является лицензией и не даёт права на работу. Он содержит
`bus_id` и хеши hardware ID, но не содержит приватных ключей.

## Офлайн-процесс

```text
Бортовой ПК                         Компьютер владельца ключа
-----------                         --------------------------
pcrt-license-tool request
  -> license-request.json
              -------------------->
                                  pcrt-license-admin issue
                                    -> license.lic
              <--------------------
pcrt-license-tool import
  -> /etc/pcrt/license.lic
```

Импорт сначала полностью проверяет файл, после чего сохраняет его во временный
файл в целевой директории и атомарно переименовывает. Некорректная лицензия не
должна заменять уже установленную рабочую лицензию.

Создание ключей выполняется один раз на компьютере владельца:

```text
pcrt-license-admin generate-keys
  -> private-ed25519.key  # остаётся только у владельца
  -> public-ed25519.key   # добавляется в pcrt-license как публичная константа
```

Выпуск лицензии использует `private-ed25519.key`. Проверяющие программы на
автобусе используют только публичный ключ и не могут подписать новую лицензию.
Публичный ключ генерируется `ed25519-dalek`, после чего его 32 байта
встраиваются в исходный код `pcrt-license` как массив байтов. Base64 остаётся
форматом файлов ключей для `pcrt-license-admin`.

## Установка и хранение

`pcrt-license-tool import` устанавливает лицензию по пути
`/etc/pcrt/license.lic`. Это JSON-файл с расширением `.lic`, чтобы его роль не
путали с обычной конфигурацией.

На демо-устройстве все операции с лицензией выполняются от `root`. Целевой
файл имеет владельца `root:root` и права `0600`. Импорт проверяет подпись,
product, срок и совпадение обоих hardware ID до записи, сохраняет новый файл
во временный файл в `/etc/pcrt`, выставляет права и атомарно переименовывает
его в `license.lic`. Некорректная лицензия не заменяет уже установленную.

## Поведение сервисов

- `pcrt-door-gateway` не начинает чтение и публикацию состояния дверей, если
  лицензия отсутствует, подпись неверна, срок истёк или не совпадает
  оборудование.
- `pcrt-recorder` всегда продолжает записывать видео. Ошибка лицензии не
  должна лишать автобус видеоданных.
- `pcrt-processor` не начинает новую AI-обработку, если лицензия отсутствует,
  подпись неверна, срок истёк или не совпадает оборудование.
- Существующие видеосессии и записи SQLite-очереди не удаляются из-за ошибки
  лицензии.
- `pcrt-uploader` продолжает отправлять уже подготовленные результаты, чтобы
  не потерять данные после истечения лицензии.
- Лицензионные ошибки записываются в журнал без вывода исходных hardware ID и
  других чувствительных данных.

`pcrt-door-gateway` и `pcrt-processor` выполняют проверку при старте и
непосредственно перед началом новой лицензируемой операции. Решение о
допустимости работы остаётся одним и тем же и реализуется в `pcrt-license`.

## Что будет позже

После демо-версии можно добавить:

- серверное продление подписанным билетом;
- ручное продление файлом для офлайн-автобусов;
- отдельный ключ устройства для аутентификации запросов продления;
- защиту от отката системных часов с локальным состоянием и, при наличии,
  TPM;
- привязку и контроль целостности модели ИИ;
- подписанные обновления программы.
