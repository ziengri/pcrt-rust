# Door contracts v1

`frames/v1` contains static hexadecimal RS-232 packet fixtures. Comments are not
part of packet data. The parser tests decode the hex independently of production
packet construction, so the fixtures cannot be accidentally generated by the code
under test.

`snapshots/v1` contains one-frame ZeroMQ topic/payload compatibility fixtures. The
transport sends each fixture as `<topic><space><compact JSON>`.

`streams/v1` contains raw chunk scenarios for the test transport. They are consumed
by `pcrt-door-protocol-publisher`; the publisher forwards bytes unchanged and does
not invoke the parser.

## Local transport test

The physical serial adapter is not needed for local verification. Build the
test-only transport feature and run:

```text
cargo test -p pcrt-door-gateway --features test-transport
```

This starts the raw protocol publisher, `pcrt-door-gateway` and a real `ZeroMQ`
subscriber. The path under test is:

```text
fixture raw chunks -> Unix stream -> StreamDecoder -> parser/FSM -> ZeroMQ PUB -> SUB
```

The production binary is built without `test-transport` and accepts only
`--serial-port`, for example:

```text
pcrt-door-gateway --serial-port /dev/ttyS0 --serial-baudrate 19200
```
